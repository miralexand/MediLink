# 医联（MediLink）安全与合规说明

本文档面向医院信息安全管理部门，说明 MediLink 在等保 2.0 三级与医院内部
安全制度下的设计与使用建议。

## 一、数据不出内网

- RustDesk 的 hbbs / hbbr 与 MediLink 管理服务端全部部署在医院内网；
- 客户端预置内网服务器地址与 Key，不使用公网 STUN/TURN；
- 台账、审计、无人值守密码均存储在内网服务器本地 SQLite 数据库中；
- 部署时通过防火墙/ACL 限制访问来源，禁止端口映射到公网。

## 二、身份鉴别

| 对象 | 机制 |
|---|---|
| 管理员 | 用户名 + 口令（Argon2id 哈希），登录后签发随机会话 Token |
| 会话 Token | 服务端仅保存 SHA-256 哈希，默认 8 小时过期 |
| 被控端注册 | `X-Agent-Key`（Enrollment Key）校验，可关闭自动注册 |
| 远程连接 | RustDesk 设备 ID + Key 加密握手 + 无人值守密码 |

> 建议对管理员账号启用医院统一身份认证（后续路线图），并定期轮换口令。

## 三、最小权限

- 系统默认 **只读**（`default_readonly=1`），需要操作时再按需授权；
- 默认 **连接需被控端确认**（`require_approval=1`），无人值守场景再由信息科评估开启；
- 管理控制台仅信息科授权人员部署与使用。

## 四、审计与留存

- 记录登录、发起远程协助、结束会话、改密、轮换密码、删除设备、修改设置等行为；
- 审计字段包含：操作人、目标设备、开始/结束时间、时长、结果、来源 IP、备注；
- 默认留存 **180 天**（可在系统设置中调整，满足等保不少于 6 个月要求）；
- 支持按条件查询与 CSV 导出，便于审计取证；
- 达到留存上限后可通过“清理超期审计日志”释放空间。

## 五、加密与存储

| 数据 | 保护方式 |
|---|---|
| 管理员口令 | Argon2id 单向哈希 |
| 会话 Token | SHA-256 哈希存储，原文只存在于客户端 |
| 无人值守密码 | AES-256-GCM 加密存储，密钥由 `MEDILINK_SECRET_KEY` 或数据库独立密钥保管 |
| 远程画面与控制 | RustDesk 端到端加密传输 |

```bash
# 生成数据库加密密钥
openssl rand -base64 32
```

## 六、等保 2.0 三级对照（节选）

| 控制项 | MediLink 措施 |
|---|---|
| 身份鉴别 | 强口令 + Token 过期 + 注册密钥 |
| 访问控制 | 仅内网可达、最小权限、默认只读 |
| 安全审计 | 全量会话审计、留存≥180 天、可导出 |
| 数据完整性/保密性 | 传输加密、敏感字段加密存储 |
| 入侵防范 | 关闭自动注册、端口收敛、无公网暴露 |
| 备份恢复 | 一键备份脚本、灾备转存建议 |

## 七、安全加固清单

- [ ] 修改默认管理员口令，启用强口令策略；
- [ ] 设置 `MEDILINK_ENROLLMENT_KEY` 为强随机串；
- [ ] 通过防火墙仅放行信息科与终端网段；
- [ ] 生产环境建议启用 HTTPS 反向代理；
- [ ] 保留 `data/rustdesk` 目录的密钥备份并妥善保管；
- [ ] 定期导出审计日志并存档；
- [ ] 离职/报废设备及时从台账清理；
- [ ] 定期轮换无人值守密码。

## 八、许可证边界

- **MediLink 自身代码**：MIT，可自由用于医院内部及二次开发；
- **RustDesk 客户端与服务端（hbbs/hbbr）**：遵循 **AGPL-3.0**；
- 本项目通过调用官方 CLI 与 Docker 镜像使用 RustDesk，未修改其源码；
- 如对 RustDesk 进行修改并对外分发，须自行履行 AGPL 开源义务；
- 内部自用部署通常不构成对外分发，但请以医院法务与开源合规意见为准。
